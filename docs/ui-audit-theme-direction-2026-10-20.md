# Duoscene 全页面审查与新主题方案

日期：2026-10-20（Asia/Singapore）。状态：设计研究交付，未修改 Flutter/API 行为。

## 1. 结论

建议将「晴空」作为新的默认设计：雾白背景、白色内容表面、柔和蓝色主操作、石墨色视频舞台。保留「森林」为可选择的完整主题；同时设计「晴空·深色」，供夜间与跟随系统使用。

不是只将绿色替换成蓝色。关键变化是：背景退出内容区域，主操作数量收敛，文字与海报承担层级，同看入口更直接，状态反馈更贴近发生位置。

「大众」在本方案中指熟悉的导航、稳定的信息层级、易读的中性色表面和明确的操作色；没有证据能证明某个 HEX 色值最受所有人欢迎。以下配色是基于项目场景、用户反馈和官方规范做出的设计判断。

## 3. 为什么当前会显得压抑

1. **大面积有色暗背景**：`DS.bg=#0B1617`、`panel=#172425`，加上 `Forest` 全页图案，几乎每页都被同一种绿色氛围包围。设置、搜索、聊天这些读写任务也用了影视背景。
2. **表面层次接近**：页面、卡片、输入框均为深绿，主要依靠描边区分。卡片嵌卡片、重复分割线增加了重量。
3. **同一种强调色承担太多含义**：薄荷绿同时用于登录、收藏、聊天气泡、在线状态、进度、链接。操作、状态和装饰的含义不清楚。
4. **不只是字号问题**：现有正文 13、辅助字 11 已经偏紧凑，不能再全局缩小。搜索海报 104×146、部分长说明和层层 Panel 才是空间占用的主要来源。应按组件调整，而非统一缩放。
5. **照片和文字竞争**：聊天与设置正文下面仍能看到山林纹理；海报本身已经足够丰富，工具界面无需再添加一层场景。

建议森林主题继续保留原有氛围，但聊天、表单及工具卡片使用稳定实色承载文字。不要让切换主题改变信息架构。

## 6. 18 页之外的真实业务界面

- **房间列表**：房间状态与最近活动优先，创建/加入各一个入口。统一 PageFrame 与列表样式，避免与设计页面像两个应用。
- **创建与加入表单**：复用登录输入样式；加入提供显式粘贴操作，当前43位token继续由协议处理，不在普通文案里强调技术长度。深链接是新增能力，不能假设现已支持。
- **房间详情/等待室**：显示两席、媒体是否就绪、邀请动作；“在线”“已准备”“已同步”分开。避免已加入后还要找“打开播放器”。
- **真实观看页**：将连接、双方就绪、播放状态压成一条信息行，展开查看详情。异常才提高强调程度。区分退出页面/离开房间/关闭房间；当前 dispose 会释放连接与语音，不能通过设计假装后台通话存在。
- **网络地址/本地视频/播放列表**：日常只展示添加视频与来源；HLS强制模式、请求头折叠进高级选项。房间不支持本地文件共享/私有请求头时就地解释，保留个人播放器能力。
- **全屏控制、倍速、截图、截图库**：沿用Playra能力与状态，不另造内核。白色控件配黑色渐层；设置面板统一布局和语义色。播放器未就绪时控制禁用有说明。
- **全局状态**：加载、无结果、网络错误、权限拒绝、重连、服务失效、确认弹窗必须覆盖浅色/深色/森林；保留新错误气泡的单警告图标和关闭按钮。

## 7. 新配色决策

比较过的方向：

| 方向 | 优点 | 不选择为主方向的原因 |
| --- | --- | --- |
| 雾白＋柔蓝（推荐） | 浏览和表单清爽；可清楚区分操作与在线成功；便于搭配多色海报 | 需要靠双圆品牌与内容建立辨识度，避免做成办公工具 |
| 奶油白＋珊瑚色 | 温暖、适合关系主题 | 大面积暖色会与爱情/短剧海报竞争，红系还需与错误状态拉开 |
| 浅灰＋鼠尾草绿 | 能延续原品牌 | 用户已明确希望摆脱森林绿色氛围，变化感不够 |

采用推荐方向。建议界面非媒体区域以中性表面为主，强调色只用于重要操作、选择和少量关系提示；比例是设计控制方法，不是精确统计或行业标准。

## 8. 尺寸与字体系

以390dp宽手机为参考，不按截图物理像素整体放大或缩小。

- 字体：普通界面用平台中文无衬线；原品牌字保留。艺术字只放品牌与片名展示，不能放设置/聊天。
- 字级：品牌28–32；页面标题18/600；分组16/600；列表标题14/600；正文14/400；辅助12/400；徽标11仅限非关键短标签。
- 不把当前所有13改成16。高频阅读文字提升到14，配合更紧凑容器；时间、集数和辅助信息12。行高正文1.45–1.55，标签1.3。
- 水平间距16，表单24；组件内12/16；相邻项8/12；分组24。
- 输入、主按钮视觉高度48；菜单至少52、触控至少48×48；主图标20、辅助18、箭头14–16。
- 圆角：输入/按钮12，内容卡14，弹层20，头像圆形；不把所有操作都做成长药丸。
- 图标：24单位SVG画布，线宽约1.7–1.8、圆端点。所有箭头用同组SVG；图标中心对齐，文字区域按基线布局。
- 卡片使用白色/层级表面即可；常规信息行无需外框。阴影只用于浮层和必要悬浮控件。
- 320dp宽及160%/200%文字放大时允许自动增高、换行/减少列数，不裁剪文字。

## 9. 动效和吸顶

现有 DSMotion 160/220/280ms 和 ScrollChrome 按滚动距离改变透明度值得保留。以下为项目目标值，不是照抄某个SDK参数。

| 场景 | 设计 |
| --- | --- |
| 顶层底部导航 | 160–200ms轻淡入；保留每页状态/滚动位置，不把整个页面当长距离横滑轮播 |
| 页内Tab | 220ms下划线连续移动，内容小幅位移8–12dp＋淡入；点击无背景色；连续点击可从当前动画位置反向 |
| 二级页面 | 240–280ms有方向进退；符合系统返回手势；不对播放纹理做缩放动画 |
| 首页吸顶 | 无顶图处使用稳定底色；有顶图时随滚动0–72dp渐变到实色，文字/图标同步切换可读色 |
| 详情吸顶 | 根据实际标题/封面边界决定折叠阈值，避免仅按全屏高度估算；收起时显影片标题 |
| 弹层 | 240–280ms，键盘展开保持输入可见；返回先收键盘再关弹层 |
| 轮播 | 保留约6秒自动轮换、400–480ms过渡；提供持续暂停，交互后暂停；后台/覆盖路由/减少动画时停转 |
| 聊天 | 自己发消息或在底部才自动跟随；历史阅读时只出现新消息提示；消息重试原位置更新 |
| 主题 | 180–220ms颜色过渡；不重建Navigator、媒体、房间连接，不闪白或重置输入 |
| 减少动画 | 去除位移、弹跳、自动轮播；状态变化仍立即可见 |

## 10. 主题切换方案

入口：「我的 → 外观」。

1. 主题：**晴空** / **森林**。晴空显示浅/深预览；森林保留原氛围与资源。
2. 晴空明暗：**跟随系统 / 浅色 / 深色**。推荐新安装跟随系统，白天系统浅色时使用晴空浅色；参考页默认展示浅色方便评审。
3. 森林本身为深色主题，选中后不再展示无效的浅色开关，明确标注“深色主题”。
4. 设备本地记忆，登录前可读取。现有用户升级应先保留森林并提供一次切换提示，避免无预告丢失旧主题偏好。
5. 视频画布与全屏始终使用媒体色；非全屏的聊天/列表跟随选定主题，不强制整页变黑。

实现结构建议：

- `ThemePreferences`：保存主题id、晴空明暗偏好；独立于登录 Session。
- 现有 `ThemeData/ColorScheme` 承担标准组件；扩展主题承载聊天、错误气泡、背景类型和媒体覆盖色。
- `DS` 继续管理尺寸与动效；颜色从当前上下文读取，移除颜色相关 const 写死调用。
- `Forest` 演进为背景容器：晴空用实色，森林用当前图片；头像去掉固定绿滤镜依赖。
- 同一widget树切主题，避免用主题名作为MaterialApp/PlayerPage的key；原身份隔离key保留。
- Playra只接颜色映射和面板样式；媒体实例、协议和音视频状态保持既有生命周期。

## 12. 参考依据

以下规范支持语义角色、可访问性与主题行为；本方案色值和尺寸是项目选择。

- [Material 3 色彩角色](https://m3.material.io/m3/pages/color-roles?s=m3)：surface、primary、on色应按语义配对，不能任意混搭。
- [Material 3 字体角色](https://m3.material.io/styles/typography/applying-type)：区分标题、正文、标签的任务。
- [Android 可访问性](https://developer.android.com/guide/topics/ui/accessibility/apps)：建议交互目标至少48dp。
- [WCAG 2.2 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字4.5:1，大字3:1；这里按更保守的普通文字标准检查关键文本。
- [Apple Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)：浅深外观需分别设计；沉浸式媒体可以保留暗色；支持随系统变化。该指南倾向系统控制，本项目按用户要求额外保留主题选择。
- [YouTube 外观设置](https://support.google.com/youtube/answer/7385323?hl=en-AZ)：提供浅色、深色与跟随设备，说明视频产品可以同时支持日常浅色和暗色体验；不将其网页说明当作所有移动端版本的精确布局。
- [WAI 轮播可访问性](https://www.w3.org/WAI/tutorials/carousels/)：自动轮播应允许用户暂停。
- [Material 3 动效](https://m3.material.io/styles/motion/overview/how-it-works)：动效应有一致的方案，项目选择克制、可打断的过渡而非处处弹跳。
